## 연습 1 (코드 읽기) Lambda 실행 흐름 추적

`lambda/guardian/handler.py`를 열어 다음 질문에 답하세요:

**Q**: `lambda_handler({"time": "2024-01-01T00:00:00Z", "source": "aws.events"}, None)`를 처음 호출했을 때, 코드가 어떤 순서로 실행되나요? 최소 5단계로 설명하세요.

> [!answer]- 정답 보기
> 1. `lambda_handler(event, context)` 호출
> 2. `_lazy.orchestrator` 프로퍼티 접근 → `_orchestrator is None` 확인
> 3. `threading.Lock()` 획득 → double-check → `_build()` 호출
> 4. `_build()`에서: Config 로드 → CostChecker, EC2Checker, S3Checker, DynamoDBStorage, TelegramResponder, DiscordResponder, AutoRemediationResponder 생성 → GuardianOrchestrator 생성
> 5. `GuardianOrchestrator.run_all_checks(event)` 실행 → 세 체커 병렬/직렬 실행
> 6. 이상 감지 시 Responder들 호출 → DynamoDB 저장
> 7. `{"statusCode": 200, ...}` 반환

## 연습 2 (설정) 비용 임계값 변경

**목표**: 비용 임계값을 $10 → $5로 낮추어 테스트하세요.

**단계**:
1. `docker-compose up -d`로 LocalStack 시작
2. 환경변수 변경 없이 `CostChecker(config={"cost_threshold": 5.0}).check()` 실행
3. mock daily_cost($5.50) > $5.00이므로 어떤 결과가 반환되나요?

> [!answer]- 정답 보기
> ```python
> from lambda.guardian.checkers.cost import CostChecker
> import os
> os.environ["AWS_ENV"] = "localstack"
>
> checker = CostChecker(config={"cost_threshold": 5.0})
> result = checker.check()
> print(result.severity)   # "HIGH"
> print(result.message)    # "오늘 비용: $5.50 임계값 초과"
> ```
> `MOCK_DAILY_COST_DEFAULT = 5.50 > 5.0` → HIGH 심각도 CheckResult 반환

## 연습 3 (디버깅) DynamoDB 저장 실패 추적

테스트 실행 중 다음 로그가 보입니다:
```
WARNING - DynamoDB table not available
```

**Q**: 이 로그가 발생하는 원인 3가지와 각각의 해결 방법을 설명하세요.

> [!answer]- 정답 보기
> **원인 1**: LocalStack이 실행되지 않음
> 해결: `docker-compose up -d` 실행 후 재시도
>
> **원인 2**: DynamoDB 테이블 미생성
> 해결:
> ```bash
> awslocal dynamodb create-table \
>   --table-name aws-guardian-events \
>   --attribute-definitions AttributeName=event_id,AttributeType=S \
>   --key-schema AttributeName=event_id,KeyType=HASH \
>   --billing-mode PAY_PER_REQUEST
> ```
>
> **원인 3**: `DYNAMODB_TABLE_NAME` 환경변수가 실제 테이블명과 다름
> 해결: `os.environ["DYNAMODB_TABLE_NAME"] = "aws-guardian-events"` 설정

## 연습 4 (확장) 새 체커 스켈레톤 작성

`RDSChecker`의 빈 스켈레톤을 작성하세요.
(RDS 퍼블릭 접근 허용 인스턴스 탐지)

> [!answer]- 정답 보기
> ```python
> # lambda/guardian/checkers/rds.py
> import boto3
> from guardian.checkers.base import BaseChecker, CheckResult
> from guardian.config import Config
>
> class RDSChecker(BaseChecker):
>     def __init__(self, clients=None, config=None,
>                  account_id=None, credentials=None):
>         super().__init__(clients or {}, config or {}, account_id, credentials)
>         self.rds_client = (clients or {}).get("rds")
>         if self.rds_client is None:
>             self.rds_client = boto3.client("rds", **Config.get_boto3_kwargs())
>
>     def check(self) -> CheckResult:
>         self._log_check_start("RDS")
>         try:
>             instances = self.rds_client.describe_db_instances()["DBInstances"]
>             public = [i for i in instances if i.get("PubliclyAccessible")]
>             if public:
>                 return CheckResult(
>                     severity="HIGH",
>                     title="RDS 퍼블릭 접근 허용",
>                     message=f"{len(public)}개 RDS 인스턴스가 퍼블릭 접근 허용",
>                     details={"public_instances": [i["DBInstanceIdentifier"]
>                                                   for i in public]},
>                     suggested_action="RDS 퍼블릭 접근을 비활성화하세요"
>                 )
>             return CheckResult.info("RDS 정상", "퍼블릭 접근 허용 인스턴스 없음")
>         except Exception as e:
>             return self._handle_generic_error("RDS", e)
> ```

## 연습 5 (보안) Telegram 메시지 인젝션 테스트

다음 코드가 취약한지 분석하고, 수정하세요:

```python
def send_alert(self, bucket_name: str):
    message = f"<b>퍼블릭 버킷 감지:</b> {bucket_name}"
    self.send_message(message, parse_mode="HTML")
```

버킷 이름이 `</b><b onclick="...">attack`이라면?

> [!answer]- 정답 보기
> **취약점**: bucket_name이 HTML로 파싱되어 구조가 깨집니다.
> `</b>` → 볼드 태그 강제 종료
> `<b onclick="...">` → Telegram Bot API는 onclick을 지원하지 않지만 메시지 구조 파괴
>
> **수정**:
> ```python
> from guardian.responders.alert_formatter import esc
>
> def send_alert(self, bucket_name: str):
>     message = f"<b>퍼블릭 버킷 감지:</b> {esc(bucket_name)}"
>     self.send_message(message, parse_mode="HTML")
> ```
> `esc("</b><b>attack")` → `&lt;/b&gt;&lt;b&gt;attack`

## 연습 6 (코드 읽기) Discord 서명 검증 흐름

`lambda/discord_webhook/handler.py`의 `verify_discord_request` 함수를 읽고:

**Q**: `timestamp + request_body`를 검증 메시지로 사용하는 이유는? `request_body`만 사용하면 안 되나요?

> [!answer]- 정답 보기
> **타임스탬프 포함 이유**: 재생 공격(Replay Attack) 방지
>
> `request_body`만 서명하면: 공격자가 유효한 서명이 달린 이전 요청을 캡처하여 나중에 다시 전송할 수 있습니다.
>
> `timestamp + request_body`를 서명하면: 같은 요청이라도 다른 시간에는 다른 서명이 생성됩니다. Discord는 타임스탬프가 현재 시간에서 5초 이상 차이나면 요청을 거부합니다.

## 연습 7 (설계) 멀티 채널 알림 설계

현재 Guardian은 Telegram과 Discord만 지원합니다.
PagerDuty 연동을 추가하려면 어떤 파일들을 어떻게 수정해야 하나요? 설계를 작성하세요.

> [!answer]- 정답 보기
> 1. **`lambda/guardian/responders/pagerduty.py`** 신규 생성
>    ```python
>    class PagerDutyResponder:
>        def __init__(self, integration_key=None):
>            self.key = integration_key or os.getenv("PAGERDUTY_INTEGRATION_KEY")
>
>        def send_alert(self, alert: AlertMessage) -> bool:
>            # PagerDuty Events API v2 호출
>            payload = {
>                "routing_key": self.key,
>                "event_action": "trigger",
>                "payload": {
>                    "summary": alert.title,
>                    "severity": alert.severity.lower(),
>                    "source": "aws-guardian",
>                }
>            }
>            requests.post("https://events.pagerduty.com/v2/enqueue", json=payload)
>    ```
>
> 2. **`lambda/guardian/config.py`**: `get_pagerduty_config()` 추가
> 3. **`lambda/guardian/handler.py`**: `_build()`에 PagerDutyResponder 초기화 추가
> 4. **`GuardianOrchestrator`**: `pagerduty_responder` 파라미터 추가
> 5. **환경변수**: `PAGERDUTY_INTEGRATION_KEY` 또는 SSM 경로 추가
> 6. HIGH/CRITICAL 이벤트만 PagerDuty로 에스컬레이션하는 필터 추가
