## 아키텍처 패턴

> [!important] 핵심 패턴 3가지
> 1. **Lazy Initialization** — cold start 비용 절감
> 2. **Checker/Responder 분리** — 감시와 알림의 책임 분리
> 3. **Base Class 추상화** — 모든 체커가 `BaseChecker` 상속

### 1. 서버리스 (Serverless)

- AWS Lambda: 코드 실행 (Python 3.12)
- AWS EventBridge: 1시간 스케줄 트리거
- 장점: 인프라 관리 불필요, 무료 티어 범위 내 운영 가능
- 단점: Cold start 지연 (→ `_LazyOrchestrator`로 완화)

### 2. 이벤트 기반 (Event-Driven)

```
EventBridge 이벤트 → Lambda 트리거 → 체커 실행 → 결과 처리
```

- 이벤트 스키마: `{"time": "...", "source": "aws.events"}`
- Discord 이벤트: HTTP POST → Lambda URL

### 3. Layered Architecture

```
┌─────────────────┐
│   Entry Point   │  handler.py (Lambda 진입)
├─────────────────┤
│  Orchestration  │  orchestrator.py (체커 조율)
├─────────────────┤
│    Checkers     │  cost/ec2/s3/cloudtrail/iam
├─────────────────┤
│   Responders    │  telegram/discord/remediation
├─────────────────┤
│    Storage      │  dynamodb
└─────────────────┘
```

## 보안 설계 원칙

| 원칙 | 구현 방식 |
|------|----------|
| 시크릿 분리 | 환경변수 대신 SSM Parameter Store 사용 |
| 최소 권한 | IAM 역할로 필요한 API만 허용 |
| 서명 검증 | Discord 요청에 Ed25519 서명 검증 |
| 입력 검증 | 인스턴스 ID, 리전, 임계값 정규식 검증 |
| HTML 인젝션 방지 | Telegram 메시지 HTML 이스케이프 처리 |

## 기술 스택 요약

| 레이어 | 기술 | 파일 |
|--------|------|------|
| 런타임 | AWS Lambda (Python 3.12) | `lambda/` |
| 스케줄러 | AWS EventBridge | `terraform/eventbridge.tf` |
| 비용 조회 | AWS Cost Explorer (boto3) | `checkers/cost.py` |
| 인프라 제어 | AWS SDK boto3 | 모든 체커 |
| 알림 | Telegram Bot API / Discord Webhook | `responders/` |
| 저장소 | AWS DynamoDB | `storage/dynamodb.py` |
| 설정 | AWS SSM Parameter Store | `config.py` |
| 로컬 개발 | LocalStack + Docker Compose | `docker-compose.yml` |
| IaC | Terraform | `terraform/` |
