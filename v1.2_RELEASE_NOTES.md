## What's New in v1.2

### 1. Performance Optimizations (Sprint 19)

**Asyncio Parallelization**
- All checker methods now support async execution (`check_async()`)
- Multi-region checks run in parallel instead of sequentially
- **Performance gain**: 4-region check reduced from ~10s to ~3-4s (2.5-3.3x faster)
- Orchestrator uses `asyncio.gather()` for concurrent execution

**In-Memory Caching**
- TTL-based caching for API responses (configurable 5-60 minutes)
- Reduces redundant AWS API calls
- **Memory impact**: ~5-10MB per 1000 cache entries
- Configurable cache backend (in-memory by default)

**Example Performance Improvements**:
```
Single region check:    ~250-300ms (unchanged)
4-region check (v1.1):  ~10000ms (sequential)
4-region check (v1.2):  ~3000ms (parallel)
Response with cache:    ~50-100ms (first request after cache TTL)
```

## Breaking Changes

⚠️ **API Changes** (from v1.1 to v1.2):

**Checker Method Names**:
- `check_cost_anomaly()` → `check()`
- `check_ec2_anomalies()` → `check()`
- `check_s3_anomalies()` → `check()`
- `check_cloudtrail_anomalies()` → `check()`

**Return Type Changes**:
```python
# v1.1 (deprecated)
is_anomaly, data = checker.check_cost_anomaly()

# v1.2 (new)
result = checker.check()  # Returns CheckResult
assert result.severity in ["INFO", "LOW", "MEDIUM", "HIGH", "CRITICAL"]
assert isinstance(result.details, dict)
```

**Migration Required**: Any code calling old method names must update to use `check()`. This affects:
- Direct checker invocations
- Test suites  
- Custom monitoring workflows

**Backward Compatibility**: Old method names will raise `AttributeError` if called. Migration is straightforward (see deployment guide below).

## Migration Guide: v1.1 → v1.2

### Step 1: Code Updates

**Update checker method calls**:
```python
# Before (v1.1)
is_anomaly, data = cost_checker.check_cost_anomaly()
if is_anomaly:
    print(f"Anomaly found: {data}")

# After (v1.2)
result = cost_checker.check()
if result.severity != "INFO":
    print(f"Alert: {result.title}")
    print(f"Details: {result.details}")
```

**Update test mocks**:
```python
# Before (v1.1)
mock_checker.check.return_value = True

# After (v1.2)
from unittest.mock import AsyncMock
result = CheckResult(severity="HIGH", title="...", details={})
mock_checker.check_async = AsyncMock(return_value=result)
```

### Step 2: Deploy

```bash
# 1. Backup current deployment
aws s3 cp s3://guardian-bucket/lambda.zip lambda-v1.1.zip

# 2. Deploy v1.2
cd lambda
sam build
sam deploy --guided

# 3. Verify
aws lambda invoke --function-name guardian-checker /tmp/response.json
cat /tmp/response.json
```

### Step 3: Test

```bash
# Run full test suite
python -m pytest tests/ -v

# Verify Telegram/Discord integration
# Send test event via EventBridge or invoke manually
aws lambda invoke \
  --function-name guardian-checker \
  --payload '{"check_type": "all"}' \
  /tmp/response.json
```

### Step 4: Rollback (if needed)

```bash
# Restore previous version
aws lambda update-function-code \
  --function-name guardian-checker \
  --s3-bucket guardian-bucket \
  --s3-key lambda-v1.1.zip

# Update CloudFormation stack
sam deploy --s3-prefix lambda-v1.1/
```

## Known Limitations

### SAM Environment
- Cold start includes SAM container startup (~1500ms overhead)
- Actual AWS Lambda cold start will be faster (~500ms)
- 3 SAM performance tests deferred to production validation

### Caching
- In-memory cache limited by Lambda memory (configurable)
- Cache cleared on function restart (by design)
- For persistent cache, implement Redis backend (v1.3)

### Async Support
- Requires Python 3.10+ asyncio
- All checkers support both sync and async methods
- Backward compatible (sync methods still work)
